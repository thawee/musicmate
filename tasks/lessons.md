# Lessons Learned: MusicMate Notification & Scroll Refactoring

## Learnings & Patterns
- **No MediaSession by Intention**: When working with apps that act as headless receivers/controllers (e.g. casting to DLNA) and do not play audio locally, the lack of `MediaSession` is an intentional architectural pattern to prevent the service from competing for system audio focus or hijacking Bluetooth/wired headphone buttons.
- **Differentiate UI Scope (WebUI vs. Native UI)**: Before implementing UI features (like list auto-scrolling) in hybrid apps, clarify if the target is the Android Native UI or the WebUI to avoid redundant changes.
- **Asynchronous Adapter Layout Race Condition**: When using pagination in a `RecyclerView` (e.g. loading pages of 500 items), calling `adapter.getMusicTagPosition(item)` right after updating a LiveData will return `NO_POSITION` if the layout/setMusicTags step is posted asynchronously. Wrapping the lookup and scroll in `recyclerView.post(...)` ensures it runs after the adapter is updated.
- **Avoid Dynamic Button Labels**: Dynamic button text (e.g., changing from "Import" to "Analyze" based on the track's management state) creates inconsistent UI and confuses the user. Prefer a stable, clear label like "Organize" that matches both contexts elegantly.
- **Cache-First Lookup in Hot Paths**: When resolving media resources (e.g., cover art) in hot paths like list scrolling or image loading, always check for pre-resolved cache keys/files first in $O(1)$ time. Synchronously scanning folders (`listFiles()`) for every bound item causes severe disk I/O bottlenecks and UI lag.
- **SelectionTracker Click Interception**: Setting an explicit `OnClickListener` on viewholder item roots overrides standard short-click selection behavior in `SelectionTracker` and launches default click activities concurrently. Inside the click listener, check if selection is active using `tracker.hasSelection()` and toggle the key selection programmatically.
- **Dismissing Contextual Action Mode**: A `SelectionObserver` should automatically dismiss the active `ActionMode` using `actionMode.finish()` when the tracker's selection count reaches `0`.
- **RecyclerView Disabling Anti-Pattern**: Dynamically calling `setEnabled(false)` on a `RecyclerView` while scrolling disrupts touch dispatch loops, leading to abrupt halts, touch-out-of-sync events, and accidental item clicks once enabled.
- **Scroll-Stopping Touch Selection Guard**: When the user touches a moving/flinging list to stop it, the transition to idle happens instantly. A subsequent long-press or tap can get erroneously registered as selection. By using a `SimpleOnItemTouchListener` to intercept the `ACTION_DOWN` event when the list is not idle, we can set an `isScrollStoppingTouch` flag to block selection during that touch cycle.

- **Filtered List Subtitle Counts**: When displaying total item counts, storage size, and duration in header/subtitle views while a local filter (like search or category filter) is active, prioritize the adapter's filtered dataset properties (`getTotalItems()`, `getTotalSize()`, `getTotalDuration()`) over database-wide category statistics, preventing inconsistent subtitles (e.g. showing category totals in a filtered list).
- **Directory Image Loader Safeguard**: When resolving cover art resource paths, verify if the resolved path is a directory (using `file.isDirectory()`). Passing directory paths to image loading frameworks (like Coil) causes silent decode failures or broken images; instead, filter directories out and fallback to the default/missing cover image.

## Actionable Rules for Future Changes
- Always ask/confirm if the app is designed to run headlessly or casting-only before suggesting standard local playback components (like `MediaSession`).
- Confirm the target screen/view (Native vs. WebUI) when implementing UI enhancement requests.
- Always use `view.post(...)` for coordinate-based or position-based operations on lists (like `RecyclerView`) that rely on recently updated adapter datasets.
- Ensure image loaders and resource retrievers resolve cached paths first and bypass directory scanning/listing functions unless cached lookups fail.
- Differentiate between requests to review flow logic versus requests to relocate or reorganize layout elements (e.g., moving items between side menus), and verify with the user before performing layout changes.
- Keep main action bar buttons stable in naming and placement; do not dynamically change primary action button text unless explicitly requested.
- For music library/audiophile tools, "Organize" is a premium and natural term that covers both file placement (importing) and audio analysis.
- When using `SelectionTracker`, always ensure that the item's standard click listener checks `tracker.hasSelection()` first to toggle selection rather than firing the default action (like opening edit details).
- Automatically finish the contextual `ActionMode` inside selection observers when selection count reaches zero.
- Never disable or enable `RecyclerView` dynamically using `setEnabled` during scroll states.
- Block item click and selection states using a touch interceptor flag (`isScrollStoppingTouch`) when the first `ACTION_DOWN` of a touch event starts during a scroll/fling state.
- Ensure that any UI header subtitle updates check if a filter is active (`adapter.hasFilter()`) and pull counts directly from the adapter instead of database statistics.
- Safeguard all image-fetching helpers by checking `covertFile.isDirectory()` before passing the file path to image loading libraries.
- **Thai Encoding Recovery & Performance**: When recovering garbled Thai text (TIS-620/Windows-874 misread as Latin-1), extract raw bytes using `ISO-8859-1` and decode using `windows-874`. Add a fast $O(N)$ check for high ASCII (`0xA1`-`0xFB`) to immediately bypass standard English/non-Thai text with zero allocations, avoiding massive CPU/GC overhead from failed conversion attempts.
- **Real-Time Interactive Previews**: In complex editors with multiple component builders (e.g. tag-from-filename parser with tag pills), register a change listener on the custom component to automatically refresh preview fields whenever items are added, removed, or dragged. This eliminates the need for manual "Preview" triggers and makes the UI feel smooth, alive, and responsive.
- **"More Actions" Menu Prioritization & Labeling**: Prioritize core/frequent user workflows (like metadata curation and tag search) at the top of contextual and overflow menus. Use active, descriptive, and premium labels (e.g., "Verify Lossless Quality" rather than technical internal project names like "MusicMate Spectra") to make technical tools feel high-end and accessible.

- **File Move/Rename Metadata Update**: When moving or renaming a file physically on disk (e.g. `Files.move`), all file operations referencing the old path (such as checking `lastModified()`) will fail or return `0` because the file no longer exists at the source. Always read properties like size and lastModified from the **new/target** file path to ensure database records are kept in sync and prevent false modifications from triggering rescans.

## Actionable Rules for Future Changes
- Always use `ISO_8859_1` to recover raw bytes from Latin-1 strings before decoding with standard target charsets (like `windows-874`).
- Implement low-overhead pre-screening checks (e.g. `hasHighAscii`) in metadata parsers to prevent wastefully invoking heavy converters/decoders on standard ASCII text.
- Connect direct event observers or change listeners on custom drag/drop tag components to automatically refresh dependent preview inputs in real-time, matching modern interactive UX patterns.
- Contextual/overflow menus (like the "More Actions" tag menu) must sort tasks by frequency of use: primary curation/editing tasks first, followed by correction utilities, and technical inspection/lookup tools last. Label menu items using active, user-centric verbs rather than technical or library-internal titles.
- When performing file movements, renames, or format conversions, always query metadata properties (like `lastModified` or `fileSize`) from the **new target file** instance, never the source file instance.- **UPnP Discovery Race Condition**: Hard-coding a fixed delay (e.g. 2500ms) after triggering `controlPoint.search()` to reopen a player picker popup is unreliable. The default `MX=3` (max-wait) means devices can respond up to 3s later, so 2500ms often reopens before responses arrive. Fix: (1) use `MX=5` for manual rescans, (2) poll `getPlaybackTargets()` every 500ms and reopen the popup as soon as remote players appear, with a max timeout (e.g. 6s/12 attempts).

## Actionable Rules for Future Changes
- Never use a fixed `postDelayed` after a UPnP M-SEARCH to reopen UI; always poll for results and gate on actual data arrival.
- For manual player rescans, always use a longer `MX` value (≥5) than the periodic background discovery to give slow/sleeping devices time to respond.

- **Kotlin StateFlow Reference Equality**: `MutableStateFlow.setValue()` silently drops updates when `oldValue == newValue` (reference equality). Never mutate a StateFlow value object in-place — always create a new copy before `setValue()`. Add a `copy()` method to mutable state classes used with StateFlow.
- **Scheduled Timer Cleanup on Context Switch**: When switching players, always cancel any pending `ScheduledFuture` tasks (like gapless fallback timers). If not cancelled, they fire and read `currentPlayerFlow` which now points to the *new* player, causing unintended track skips. Call `resetGaplessState()` at the top of `deactivatePlayer()`.
- **Stop-Before-Switch**: When switching playback targets, always stop playback on the old player before deactivating. Without an explicit stop, audio continues playing on the old renderer/app while the new player starts — producing dual audio.
- **Backend Call Error Resilience**: All calls to `mediaHub` (SOAP/UPnP) and `androidPlayer` (IPC/MediaController) can throw unchecked exceptions from network timeouts, SOAP faults, or dead sessions. Wrap every backend call in try-catch and log+recover. On the scheduler thread, an unhandled exception kills the thread and silently breaks all future scheduled tasks.
- **Synchronized Compound Queue Operations**: When an index read (`volatile int`) is followed by a list access, the compound operation is a TOCTOU race. Mark `getNextTrack()`, `getPreviousTrack()`, and `setCurrentTrack()` as `synchronized` — consistent with the existing `setPlaybackTrack()` and `updateShuffleOrder()` methods.
- **Volatile for Cross-Thread Fields**: Fields written on one thread and read on another (like `runningMode`, `controlledPlayerTargetId`) must be `volatile` for visibility guarantees. Plain fields have no JMM visibility guarantee — the reading thread may see stale values indefinitely.
- **PlaybackCallback Defaults**: Abstract or base callback classes must provide safe empty `{}` implementations for optional methods instead of throwing `RuntimeException("Stub!")`, preventing crashes when callers invoke un-overridden methods.
- **Service Lifecycle Leaks**: Always store `LiveData` observers created with `observeForever()` in fields and unregister them in `onDestroy()`. Always cancel `Job`/`CoroutineScope` instances on service destruction.
- **Main Thread I/O Guard**: Disk asset copying, file deletions, and web server file preparation must never run synchronously on the Android main thread during `onCreate()`. Offload to a dedicated background executor thread.
- **Queue Index Persistence**: Loading playing queue from DB without initializing `currentIndex` leaves pointers at `-1`, causing `getNextTrack()` and `getPreviousTrack()` to return null/fail after app restart. Always set `currentIndex = 0` and `playbackIndex = 0` when `loadPlayingQueue()` loads a non-empty queue, and update `indexMap` when tracks are added.
- **DLNA Fallback Timer Scheduling**: Never schedule safety fallback timers at `durationMs * 0.97` (97% of track length). On long tracks, a 97% timer fires seconds before track end and issues a manual `Stop` + `SetAVTransportURI` + `Play` call, prematurely cutting off songs and breaking native DLNA gapless (`SetNextAVTransportURI`) transitions. Schedule fallback timers at `durationMs + 1500` (100% completion + 1.5s grace period).
- **DLNA DAC Buffer Flush Grace Period**: When issuing `Stop` prior to `SetAVTransportURI` + `Play` on DLNA renderers, add a 100ms grace period before triggering `executeSetUriAndPlay`. Immediate back-to-back SOAP execution while audio buffers are active creates DAC zero-crossing pop/click artifacts on external receivers and DACs.
- **Track Deletion Playback Handover**: When deleting media files or tags, check if `deletedTrack.getId() == getNowPlayingSong().getId()`. If the deleted track is currently playing, immediately advance playback to the next track (`skipToNextInQueue()`) or stop if the queue is empty, then remove the track ID from `QueueManager` to prevent playing deleted audio sources or throwing 404 stream errors.
- **Queue Index Shifting on Element Removal**: When removing an element at `position` from a list managed by index pointers (like `currentIndex` and `playbackIndex`), always check if `position < currentIndex` or `position < playbackIndex`. If true, decrement the index pointers by 1 to match the left-shift of elements, preventing queue pointers from skipping tracks on subsequent `getNextTrack()` invocations.
- **Executor Service Guarding on Callbacks**: When scheduling delayed tasks via `ScheduledExecutorService` inside asynchronous callbacks, always check `if (!scheduler.isShutdown())` before calling `schedule(...)`. If the enclosing component or service is stopping, `schedule()` throws `RejectedExecutionException` and crashes the worker thread.
- **Reactive Dialog Song Subscriptions**: When building playback bottom sheets or dialogs (like `NowPlayingQueueSheet`), do not rely solely on initial population during service binding. Subscribe to `playbackService.subscribeNowPlayingSong(...)` and `subscribePlaybackState(...)` to receive real-time track change notifications, updating title, artist, cover art, resolution badges, and active queue selection live while the dialog is visible. Unsubscribe in `onStop()` to prevent memory leaks.
- **Queue State Persistence**: Playback options like `isShuffle` and `repeatMode` must be persisted to disk (via `SharedPreferences` or database) alongside track IDs when modified. In `QueueManager.loadPlayingQueue()`, always restore `isShuffle` and `repeatMode` prior to building `shuffleOrder`, ensuring user queue preferences survive app restarts, background kills, and system reboots.
- **Compilation Album Artist Normalization**: Never compare `albumArtist` against exact hardcoded strings like `"Various Artists"`. Use a centralized `StringUtils.isVariousArtists(albumArtist)` helper that performs fuzzy prefix matching (e.g., `various*`, `vaious*` typos, `varios*`, `va`, `v/a`, `v.a.`, `ost`, `compilation`) to prevent formatting compilation albums as `Album (by Various Artist)`.
- **DLNA Player Auto-Selection Controlled Target Initialization**: When auto-selecting a streaming player target (e.g., via `autoSelectBestPlayer()`), always invoke `switchPlayer(player, true)` with `controlled = true` so `controlledPlayerTargetId` is initialized immediately. Additionally, update `isControllable()` to self-heal when `controlledPlayerTargetId` is null for an active streaming target, preventing playback controls (Next, Prev, Play, Pause, Stop) from mistakenly routing to local media controllers instead of the DLNA renderer.
- **Swiped RecyclerView Item Notification**: When using `ItemTouchHelper` for swipe-to-remove in lists with positional indices, calling only `adapter.notifyItemRemoved(pos)` leaves an un-rebound empty gap and stale item position numbers. Always call `adapter.notifyItemRangeChanged(pos, queue.size() - pos)` after `notifyItemRemoved(pos)` (or re-populate if the queue is empty) to collapse layout spaces and update position indicators seamlessly.
- **Audio Codec Badge Styling Consistency**: Always use `apincer.android.mmate.ui.view.BadgeView` and `TagUtils.formatCodec()`, `TagUtils.getCodecColor()`, and `TagUtils.getCodecBgColor()` when displaying file format badges (e.g. FLAC, MP3, AAC, DSD, MQA) in secondary screens (such as `NowPlayingQueueSheet`) to match the exact font, outer border drawable, and lossy/lossless color scheme of the main song list (`MusicTagAdapter`).
- **Streaming & Server Control UI Placement**: Place output target management icons (like DLNA/HTTP Media Server status) inside the Now Playing sheet header alongside player output pickers (`btn_select_target_player`) and signal path technical details (`btn_open_signal_path`). This keeps the primary floating bottom dock clean and balanced (Collections on the left, main menu on the right) while grouping all streaming & output engine controls into a single intuitive header hub.
- **Now Playing Artwork Gestures & Volume Bar**: Provide horizontal touch fling gestures on album artwork (`sheet_album_art`) to quickly skip tracks (left = next, right = previous) and double-tap to toggle play/pause, as well as a dedicated volume SeekBar controlling `AudioManager.STREAM_MUSIC` inside bottom sheet dialogs to give users tactile audio control without relying solely on physical device side buttons.
- **Dynamic Palette Ambient Glow & Interactive Badges**: Use `androidx.palette.graphics.Palette` on loaded artwork bitmaps to create dynamic HSV-adjusted gradient backgrounds on Now Playing cards, giving a modern ambient visual aesthetic while keeping text readable. Make technical audio badges (`sheet_format_badge`, `sheet_tech_details`) interactive (clickable) to open detailed audio signal path dialogs (`SignalPathBottomSheet`).
- **Unified Audio Hub Bottom Sheet Architecture**: Consolidate interdependent modal bottom sheets (e.g. Now Playing/Queue, Audio Signal Path, and DLNA Media Server Management) into a single master bottom sheet (`AudioHubBottomSheet`) with a top `MaterialButtonToggleGroup` tab switcher. This eliminates clunky dismiss/re-open sheet animations, reduces UI context switching lag, and allows deep-linking to specific tabs (`newInstance(TAB_INDEX)`) without sacrificing instant access to related tools.
